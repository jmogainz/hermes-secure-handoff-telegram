# Whole-plugin audit and general-form hardening

## Scope

Backend browser discovery/binding, encryption/transport, owner routing, request lifecycle, Mini App rendering, packaging, installation and static deployment were reviewed. Tests use synthetic intercepted pages in disposable browsers, not the operator's real account or profile. No real credentials or payments were used.

## Principal decisions

- General form entry is explicit and fill-only. A recognized email/password input does not grant authority to submit a registration, settings, checkout or destructive operation.
- Final purchase execution is deliberately disabled. A boolean confirmation with only an origin is not authorization bound to amount, currency, merchant, recurrence and terms.
- Model-visible output is status/origin only. Direct type/click are blocked; raw page text and echoed values are not a safe handoff diagnostic.
- Original document/form/frame identity and option meaning are authority, not mutable re-probe results. A same-looking replacement cannot inherit the old request.
- Check authorization at the actual browser mutation boundary, not only before awaited actionability/focus work. Expiry/cancel must not resurrect through continuation or queued publication.
- Synthetic demo capability cannot disable certificate validation in an unowned production browser.
- Bounded fields/options are not enough: the whole launch request has a byte budget, and choice mappings must remain pinned.

## Evidence hierarchy

The baseline review reproduced purchase-gate bypasses, document/frame replacement, unchecked continuation, cancel races, plaintext-output paths and parser/publication defects. Initial repairs passed a full 209-test suite. A second independent review still reproduced additional uncovered cases. Those green tests were not treated as a security approval.

The follow-up regression module `tests/test_candidate_security.py` is the final-repair gate alongside `tests/test_security_boundary.py`, `tests/test_general_forms.py`, `tests/test_transport_hardening.py`, `tests/test_target_binding_real.py` and the historical integration suites. The final release must report actual executions after all repairs, not infer approval from the number of tests.

## Frontend

The professional monochrome UI was independently reviewed on synthetic mobile and desktop screenshots. Clear destination/action scope, explicit labels, touch-sized controls, field errors and focus states, and no horizontal overflow in the tested viewport matrix. Browser tests cover malformed requests, every supported generic field kind, replay-envelope integrity, expiry/cancel during delayed encryption, oversize values, and plaintext cleanup. The official SDK test uses a native bridge stub; it is not physical-device E2E.

The canonical static deployment was independently deployed and fetched back. `app.js`, `index.html` and `styles.css` matched tested local bytes, and no-store/no-referrer headers were verified.

## Final gates

That bounded review reproduced no remaining high-severity defect in the requested authority/lifecycle paths after the last classifier fix; it did not certify all browser behavior. Backend source/installed-package verification and gateway process activation are separate: a running gateway must restart externally after installed Python changes. Physical iPhone behavior and live-provider authentication are not established by these tests. The statement that cross-frame support was not established is historical to this 2026-09-07 audit; the later uncommitted candidate has separate synthetic HTTPS child-frame evidence.

## Deliberate limitations

See [compatibility](compatibility.md). Arbitrary custom widgets, contenteditable, uploads, native wallets/passkeys/CAPTCHA, shadow-root forms, unsupported iframe/provider widgets, large option lists and mismatched native constraints are not certified. The later candidate supports only eligible visible native controls in vetted HTTPS child frames and does not establish universal provider compatibility. Same-origin input events may autosave or auto-submit on the destination site. Browser-held values, Python strings and garbage-collected JavaScript cannot be claimed forensically zeroized; cleanup removes references and clears mutable buffers/controls.
