# Agent-composed encrypted ENTRY (local candidate)

This is a working bounded composition path, not remote purchase completion. It
uses the existing static Mini App and encrypted Telegram submission transport.
No new service, private relay, device pairing, or mandatory machine-certified
transaction terms are part of this ENTRY API.

## Tool flow

1. Call `telegram_secure_handoff` with `action: "attach"`, `mode: "compose"`,
   the exact HTTPS `origin`, and an optional exact Chrome target ID in `ref` if
   needed to disambiguate. Attachment does not navigate or publish a form.
   Result: `{status: "attached", session_ref}`.
2. Call `{action: "discover_components", session_ref}`. Result:
   `{status: "composition_available", snapshot_ref, expires_at_ms,
   phase: "entry", refs: [{ref, kind, required, ordinal}, ...]}`. When a
   checkout includes supported native controls in HTTPS child frames, each ref
   also includes a bounded `frameOrdinal`; it is only a layout/binding hint and
   never identifies or exposes the child origin.
3. Call `{action: "present_composition", snapshot_ref, layout, groups}`.
   `layout` is `stack` or `sections`. Each group is exactly
   `{title, refs: [field_ref, ...]}`. Titles are the runtime-owned labels
   `details`, `contact`, `address`, `payment`, or `other`.
   Result: `{status: "waiting_for_handoff", component_ref}`.
4. `composition_status` and `cancel_composition` take exactly `component_ref`.
   They return `{status, component_ref}` for a matching owner/session component.
   Wrong-scope and unknown refs both return `{status: "rejected"}`.

All refs must be copied from the current runtime result, not generated by the
agent. Owner/private chat/thread identity comes from trusted invocation context,
not arguments. Session and snapshot refs pin the exact attached page, original
document, native controls, original form/scope and action routing. Discovery
never fills, clicks or grants submission authority.

### What the agent can choose

The agent selects supported fields, orders them visually, groups them, and
chooses one of two layouts and finite group labels. **Every browser-required
field must be included exactly once. Optional fields may be omitted explicitly.**
Selection is by inclusion in `groups.refs`; an omitted optional field is not
rendered, is not requested in the encrypted payload, and is not mutated.
Selected optional fields remain optional in the UI. Empty text is allowed where
the native field is optional; selected native selects require an explicit choice.
The agent cannot change a control kind or its required status.

Field labels are generated from the supported control kind and original ordinal
(e.g. `Text 1`); group labels do not establish field semantics. Select/radio
choices use `Option 1`, etc., mapped privately to native option values. These
are not destination labels. The owner must know the intended field/option from
the original page; unknown meaning is a usability limitation, not permission to
publish private labels. No arbitrary labels, HTML, JS, CSS, selectors, URLs,
callbacks, values, defaults, hidden/collapsed groups, or custom action buttons
are accepted by composition.

## Bounds and lifecycle

- Existing maximum of four owner sessions; one active snapshot and component
  per session, at most 24 logical fields, eight nonempty groups, no nesting.
- Discovery leases last 120 seconds, including publication and encrypted apply.
  Publication does not extend expiry. A newer discovery invalidates old refs.
- A successfully reserved presentation consumes its snapshot before sending.
  All replayed presentations, including identical retries, reject; they do not
  republish. Use `composition_status` after accepted publication. If the reply
  itself was lost, `read` provides the session status without reminting.
- Failed/ambiguous publication revokes the key and bindings. Fresh discovery is
  necessary; no old URL remains usable. Close, cancel, expiry, session
  replacement, and terminal apply scrub private composition maps and bindings.
- Status is retained only for the current session's most recent component.
  Rediscovery/replacement removes the old component lookup; there is no growing
  global capability registry. After expiry/cancel, reattach to start again.
- Cancel signals revocation before waiting for the session lock. Already
  dispatched destination input events cannot be undone. This is not a guarantee
  of transactional rollback or cancellation of arbitrary site side effects.

## Wire and privacy

This is an additive v3 `mode: "form"` request with `composition` containing
`{layout, groups: [{title, fields: [wire_field_id, ...]}]}`. The runtime owns this
wire metadata. Wire `fields` remain in **original private mutation order**;
visual groups independently define display and keyboard order. Frontend parsing
requires exact coverage of the transmitted fields, with no duplicates.

All rendered inputs start empty, including selects. No source current values,
checked state, source labels, source option labels or source option values are
published by this composition path. Discovery returns only kind/required/ordinal
and opaque refs. Browser-derived semantics/options remain private and are
revalidated before decrypt and at native mutation boundaries. Option mappings
use opaque local choice IDs in the wire, resolved only during private apply.

The launch fragment is **public metadata, not encrypted delivery**. It contains
the target origin, generic fields/layout, expiry, request ID and public key.
Only owner-entered submission values are encrypted (AES-GCM + RSA-OAEP) before
Telegram `sendData`. Do not put private text in a target hostname. The trusted
static frontend publisher can read entries before encryption. There is no new
whole-runtime browser arbitration: other tools that independently inspect the
same browser are outside this tool's confidentiality boundary.

## Supported scope

Top-document native text, email, telephone, number, password, OTP, textarea,
search, URL, date/time/local datetime/month/week, supported card-like typed
fields, bounded single selects and radio groups (rendered as selects). For
checkout/composed entry, the same native control set may be discovered in a
visible HTTPS child frame descended from the exact checkout scope. The private
binding retains the owning Frame, full document URL, document handle and iframe
host chain; child handles are mutated only inside that Frame.

Checkboxes, color and range are rejected in this composition version because
their existing native renderer has a default state rather than genuinely empty
entry. Large search-selects (over 64 choices), file inputs,
general forms remain top-document only; HTTP frames and non-rendered helper frames
are not entry controls (a helper becoming visible after binding invalidates the
lease), while custom widgets,
shadow controls, browser dialogs and multiple/ambiguous scopes also fail closed.
Unsupported controls cannot be hidden to force acceptance. Legacy non-composed
form compatibility is unchanged. No universal website compatibility claim.

Cross-frame checkout entry and observed approval use a separate guard per
owning document. The final parent action is a conservative two-phase sequence:
all child frames are checked immediately before the parent click, the capability
is consumed before dispatch, and any detected navigation, host replacement,
mutation epoch or expiry rejects. OOPIFs do not expose a truly atomic browser
primitive, so a narrow last-moment race cannot be eliminated or represented as
atomic authorization. Ambiguous dispatch is never retried.

## Explicit purchase-source continuation

Ordinary ENTRY ends `filled`, with no explicit submit/Pay/Buy click. A destination
input handler may autosave or auto-submit. A payment group does not establish
purchase intent.

The follow-up [private acquisition bridge](purchase-acquisition.md) adds
`discover_purchase_sources` and `select_purchase_sources` after field discovery.
Only an explicit valid source selection arms composed checkout. After encrypted
fill, the original sources are revalidated and a fresh registry creates
`purchase_review_ready`; `inspect_purchase`/`compose_purchase` then publish a
separate explicit encrypted purchase approval. The final action is one guarded
browser click, not a guarantee of payment or provider success.

The exact public/nonpersonal catalog document still requires a trusted-host grant.
There is no automatic live grant issuer and no model-facing `public: true` bypass.
Without that grant, source discovery returns `public_source_authorization_required`.
See the acquisition document for restricted table/definition-list shapes,
retained-document requirements, no-entry refusal, privacy and lifecycle limits.
No install, deployment, live Chrome or physical Telegram/iPhone verification is
implied by this local candidate.
